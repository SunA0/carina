### Carina
- 定义：本项目仓库名及模块名 github.com/suna0/carina，是从 beego+vanilla 抽取出的独立 Go 微服务基础框架，目标是将 tapster 验证过的 vanilla 微服务能力完整移植到 Gin+GORM，并修复事务失效、单例 data race、回滚误判三个已知缺陷。
- 别名：carina 框架

### vanilla
- 定义：指被移植的对象——tapster 项目中基于 beego fork 构建的微服务框架层（RestResource 体系、约定路由、统一响应、事务生命周期、分布式锁、Filter 协议、分页、JWT、tracing、cron、WS Proxy 等）。Carina 的 vanilla/ 包是其 Gin+GORM 等价实现，保持包名以降低迁移成本。
- 别名：beego vanilla、tapster vanilla

### RestResource
- 定义：Carina 的核心契约：每个 API 资源继承 vanilla.RestResource，通过 Resource() 返回点分资源名（如 account.corp）自动生成标准/API/别名路由，并在 Prepare/Finish 生命周期中处理参数校验、分布式锁、事务 Begin/Commit、AfterCommitCallback 等横切逻辑。
- 别名：REST 资源基类

### Filter 协议
- 定义：统一的查询过滤协议，前端通过 __f-字段名-操作符 形式的查询参数（如 __f-name-contain=张&__f-age-gt=18）声明过滤条件，框架将其转换为 GORM Where 子句。支持 equal/contain/gt/gte/lt/lte/in/notin/range 等操作符。
- 别名：__f-xxx 协议、查询过滤器

### 双模式分页
- 定义：两种分页模式：backend（offset/limit，返回 has_prev/has_next/total_count/display_pages，适合后台管理）与 apiserver（游标式 _p_from/_p_count，返回 has_next/next_from_id，适合 API 服务）。
- 别名：分页模式、offset 分页、cursor 分页

### BusinessError
- 定义：框架定义的异常类型，用于区分业务错误（code=500）与系统错误（code=531），由 Recovery 中间件捕获后统一转为标准 JSON 响应，并可控制是否推送告警（如 Sentry）。
- 别名：业务错误

### IBusinessContextFactory
- 定义：稳定契约接口，允许下游自定义业务上下文工厂，将 JWT 解析后的用户信息、DB 连接等注入到请求上下文中，是框架与业务之间的边界之一。
- 别名：业务上下文工厂

### ILock
- 定义：分布式锁抽象接口，屏蔽底层实现差异（生产用 RedisLock/redsync，开发用 DummyLock），RestResource 通过 GetLockKey()/GetLockOption() 在请求生命周期内自动加锁/释放。
- 别名：锁接口

### TaskInterface
- 定义：Cron 任务抽象接口，定义 Run(TaskContext) error、GetName()、IsEnableTx() 等方法，使定时任务与 REST 共享同一套事务、recovery、tracing 运行环境。
- 别名：定时任务接口

### 下游项目
- 定义：依赖 Carina 框架的实际业务服务（如 tapster、wedding、beat-go 等），通过 go get github.com/suna0/carina@vX.Y.Z 版本化引入框架，各自维护 DB 驱动、配置、中间件等策略层代码。
- 别名：下游服务、service

### 框架仓
- 定义：Carina 所在的独立仓库，作为单一真源承载框架机制代码，下游项目通过版本号引用而非拷贝源码，解决 cp -r 模板导致的漂移与维护难题。
- 别名：框架仓库

### go-template
- 定义：被抽取前的旧模板仓库名，其 vanilla/ 仅包含简化版能力（RestResource+Router+Response+事务+中间件），Carina 计划在此基础上补全 tapster vanilla 的全部微服务能力。
- 别名：旧模板
