模块分为两层：
- `vanilla` 层定义 REST 资源契约 `RestResourceInterface`（`rest_resource.go`），业务通过内嵌 `RestResource` 基类实现 `Resource()`、`GetParameters()`、`DisableTx()`、`GetLockKey()` 等方法；`router.go` 中的 `Router()` 根据点分资源名自动生成标准路径 `/a/b/` 与 API 路径 `/a/api/b/`，并注册 GET/POST/PUT/DELETE/PATCH 五种方法。
- `handler.go` 中的 `CreateHandler` 是核心调度器：启动时通过反射预计算方法元数据到 `metaCache`，每请求创建独立实例，依次执行参数解析（`parameters.go`）、分布式锁获取、事务 Begin→Prepare→调用具体方法→BeforeCommitCallback→Commit→AfterCommitCallback→Finish 的生命周期，并通过 `metrics` 包记录端点计数与耗时。
- `middleware` 层由 `register.go` 的 `Register(engine, Options)` 一站式挂载 Recovery → Tracing → Metrics → CORS → MethodOverride → JWTAuth → Extra → RequestLog 固定顺序的中间件链；各中间件文件（`jwt_auth.go`、`cors.go`、`tracing.go`、`metrics.go`、`request_log.go`、`lock.go`、`recovery.go`、`method_override.go`）以 `gin.HandlerFunc` 形式暴露，通过 `Options` 开关控制启用。
- 依赖方向单向：`middleware` 依赖 `vanilla` 的响应构造与业务上下文工厂，`vanilla` 不反向依赖 `middleware`，保证框架解耦。
